# Maven dependency analysis

**Wired 2026-08-14 (P15 step 1a).** `maven-dependency-plugin:analyze-only` is bound to
`verify` in `backend/pom.xml` (`pluginManagement` execution `analyze-declared-dependencies`,
activated in root `build/plugins`), with `failOnWarning=true` and `ignoreNonCompile=true`.
`mvn verify` now fails on any undeclared-but-used or unused-but-declared **compile-scope**
dependency in any of the eight backend modules.

`ignoreNonCompile=true` means Runtime/Provided/Test/System-scoped dependencies are never
flagged as "unused declared" — only compile-scope entries are. Every dependency below is
compile-scope unless the entry says otherwise.

## What P15 found, and how it was resolved

Before this phase, no module declared the plugin, so nothing had ever been measured. A dry
run (`org.apache.maven.plugins:maven-dependency-plugin:3.7.1:analyze-only
-DignoreNonCompile=true`) across all eight modules surfaced three distinct problem shapes,
resolved differently:

1. **Genuinely unused dependency — removed.** `application` declared
   `org.apache.commons:commons-csv` for "CSV export endpoints" that were never
   implemented (`grep -r "CSVFormat\|CSVPrinter\|commons.csv" backend/` — zero hits
   anywhere in the repository). Removed outright rather than ignored.

2. **Used-but-undeclared — declared explicitly.** Every module used framework/library
   classes directly (annotations, `Authentication`, `JpaRepository`, `Jwt`,
   `HttpServletRequest`, generated-OpenAPI `@Schema`/`@Operation`, …) that it received only
   transitively through a Spring Boot starter or another module's transitive edge. Fixed by
   adding an explicit `<dependency>` for each such artifact, letting the Spring Boot BOM
   (`spring-boot-starter-parent`) manage the version — this is real, load-bearing
   convergence, not a workaround. A handful of these were also flagged "non-test scoped
   test only" (used only from `src/test`, e.g. `domain`, `cache-management`,
   `jakarta.persistence-api`, `spring-data-jpa` and `jackson-core` in `application`) — those
   were declared with `<scope>test</scope>` instead of compile.

3. **Unused-declared, but structurally invisible to a bytecode-reference analyzer — kept
   and ignored, documented below.** Two shapes recur:
   - **POM-only aggregators** (every `spring-boot-starter-*`,
     `logbook-spring-boot-starter`): they own no class of their own. Once the classes they
     transitively provide are declared directly (case 2 above), the aggregator itself is
     always "unused" to this analysis — but it still supplies real autoconfiguration
     (embedded Tomcat/MVC wiring, the Spring Security filter chain, AOP proxy creation,
     Actuator endpoints, bean validation) that no direct class import can represent.
   - **Classpath- or string-driven edges**: `migrations` (Liquibase changelog *resources*
     on the fat-jar classpath, no Java class), `observability` (its two classes are
     consumed inside `external-services`, never imported by `application` directly),
     `logstash-logback-encoder` (referenced by fully-qualified class name from
     `logback.xml`, not a Java import), `springdoc-openapi-starter-webmvc-ui` (classpath-
     scanned autoconfiguration), `hibernate-jcache` + `ehcache` (Hibernate's
     `hibernate.javax.cache.uri` names `ehcache.xml` as a string, never a Java import),
     `micrometer-registry-prometheus` (Actuator autoconfigures `PrometheusMeterRegistry`
     from classpath presence alone), `liquibase-core` (no custom Java changesets exist
     yet in `migrations`, only XML/SQL).

## Non-test-scope exceptions

`ignoredNonTestScopedDependencies` (a separate list from the unused-declared allowlist
above, not checked by `check-maven-dependency-analysis.py`) contains five entries, each
verified empirically by actually scoping the dependency to `test` and watching the build
break, then reverting:

- `com.fasterxml.jackson.core:jackson-core` (`external-services`, `application`) —
  `HeyGenClientImpl`/`YoutubeClientImpl`/`MetadataOnlyHttpLogFormatter` fail with "cannot
  access `com.fasterxml.jackson.core.{Versioned,TreeNode,ObjectCodec,JsonParser}`".
- `${project.groupId}:domain`, `${project.groupId}:cache-management`,
  `jakarta.persistence:jakarta.persistence-api`, `org.springframework.data:spring-data-jpa`
  (`application`) — scoping any of the four to test breaks compilation across
  `GlobalExceptionHandler`, `LogbookConfig`, `AuthProperties`/`SecurityProperties`
  (Lombok-generated accessors) and more, with misleading "cannot find symbol" diagnostics
  on unrelated Lombok-generated getters — a cascading failure, not four independent bugs.

In every case `javac` needs the artifact on the **compile** classpath to resolve a
supertype, an annotation-processed class, or a Spring configuration class that
`application`'s/`external-services`' main sources never name directly by import, so the
bytecode-reference analyzer sees zero direct main-source reference and misclassifies a real
compile-scope dependency as test-only. Do not "fix" any of these five by re-scoping to
`test` — verify against a real build first.

## One used-undeclared exception

`ignoredUsedUndeclaredDependencies` contains exactly one entry:
`${project.groupId}:external-services` for `application`. `YoutubeController`/
`YoutubeApiMapper` reference `external-services`' `YoutubeClient` and its model types
directly, which is genuinely "used undeclared" by this analyzer's definition — but
declaring the dependency directly in `application/pom.xml` is forbidden by
`structure-lint.sh`'s own architecture assertion ("application/pom.xml must not depend on
external-services — route through service/"). The edge already exists transitively via
`service -> external-services`, so the two gates are reconciled by ignoring the analyzer
finding rather than declaring the dependency.

Keep the dependency graph small going forward: when the gate identifies a genuinely unused
compile dependency, remove it (as `commons-csv` was removed here) rather than adding a new
ignore. Add an ignore only for the same two shapes documented above — a POM-only aggregator
or a classpath-/string-driven edge — and record the specific reason in this table before
adding the coordinate to `backend/pom.xml`.
